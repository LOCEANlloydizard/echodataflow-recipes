# echodataflow-recipes

This repository hosts recipes that can be used with [`Echodataflow`](https://github.com/OSOceanAcoustics/echodataflow) to deploy echosounder data processing workflows.

The recipes are stored with the following structure:
```
recipes
  |--- deploy     # deployment specification for flows
  |--- params     # parameters used by flows
  |--- resources  # ancillary files used by flows
```

## Examples

### Trigger processing from transect updates

The transect update example demonstrates how changes to an external transect
CSV can trigger an Echodataflow flow through Prefect events.

The workflow is:

```
transect CSV update
    ↓
file watcher
    ↓
Prefect event: echodataflow.transect.updated
    ↓
transect_update deployment
    ↓
identify new or updated transect segments
    ↓
find overlapping Sv files
    ↓
downstream transect-specific processing
```

The file watcher is started separately and receives the path to the transect
CSV as a command-line argument:

```bash
python scripts/watch_transect_updates.py /path/to/transect.csv
```

The deployment is configured in
`recipes/deploy/deploy_transect_test.yaml`, with its flow parameters in
`recipes/params/params_transect_test.yaml`.

For this example, the transect flow uses `Sv_files.csv`, generated by the
existing `raw2Sv` workflow, to identify Sv files whose ping-time ranges overlap
each new or updated transect segment.

The example currently stops after identifying the relevant Sv files. This
provides the event trigger and input-selection mechanism that can be used by
downstream transect-specific processing workflows.
